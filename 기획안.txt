# TeamFlow
취업용 풀스택 포트폴리오 프로젝트 기획안

## 1. 프로젝트 목적

취업용 풀스택 포트폴리오를 목적으로 하는 팀 협업 및 이슈 관리 서비스입니다.

단순 CRUD 프로젝트가 아니라 다음 역량을 보여주는 것을 목표로 합니다.

- React / Next.js 기반 프론트엔드 개발
- Java / Spring Boot 기반 백엔드 개발
- REST API 설계 및 프론트-백엔드 연동
- MySQL / JPA 기반 데이터 모델링
- Spring Security / JWT 기반 인증 및 권한 처리
- WebSocket 기반 실시간 기능 구현
- Docker 기반 실행 환경 구성
- 실제 서비스 형태의 구조 설계
- 예외 처리, 테스트, 유지보수성을 고려한 코드 작성

중요:
이 프로젝트는 단순히 기능을 빠르게 생성하는 것이 목적이 아닙니다.
취업 면접에서 프로젝트 구조, 기술 선택 이유, 데이터 흐름, 인증 방식, 트랜잭션 처리, WebSocket 동작 원리 등을 직접 설명할 수 있도록 이해하기 쉬운 구조로 구현해야 합니다.

과도한 추상화나 불필요하게 복잡한 아키텍처는 피하고, 주니어 개발자가 이해하고 설명할 수 있는 수준의 실무형 구조를 지향합니다.


## 2. 서비스 개요

여러 명의 팀원이 하나의 워크스페이스에서 프로젝트와 이슈를 관리하고 실시간으로 소통할 수 있는 협업 서비스입니다.

주요 흐름:

1. 사용자가 회원가입 및 로그인
2. 워크스페이스 생성 또는 초대
3. 워크스페이스 내부에 프로젝트 생성
4. 프로젝트별 이슈 등록
5. 담당자, 우선순위, 상태, 마감일 지정
6. 팀원 간 댓글 작성
7. 이슈 상태 변경
8. 프로젝트별 실시간 채팅
9. 주요 변경사항에 대한 알림
10. 대시보드에서 프로젝트 진행 상황 확인

- createdAt

1. 어떤 구조로 구현할지 설명
2. 필요한 파일 목록 설명
3. 데이터 흐름 설명
4. 구현
5. 구현 후 핵심 코드 설명

복잡한 기술을 사용할 경우:

- 왜 필요한지
- 다른 선택지는 무엇인지
- 왜 현재 방식을 선택했는지

설명할 것.

## 18. 최종 목표

최종적으로 다음 질문에 답할 수 있는 프로젝트를 만들어야 합니다.

- 왜 Next.js를 사용했는가?
- React는 어떤 역할을 담당하는가?
- 왜 Spring Boot를 별도 백엔드로 사용했는가?
- JWT 인증은 어떻게 동작하는가?
- Refresh Token은 왜 필요한가?
- JPA Entity 관계는 어떻게 구성했는가?
- REST와 WebSocket은 어떻게 역할을 나눴는가?
- WebSocket 인증은 어떻게 처리했는가?
- DB Transaction은 어디에서 필요한가?
- 프론트엔드와 백엔드는 어떻게 통신하는가?
- 프로젝트에서 가장 어려웠던 문제는 무엇이었는가?
- AI 도구는 어디에 사용했고 결과를 어떻게 검증했는가?

프로젝트의 최종 목적은 기능 수를 늘리는 것이 아니라,
"실제로 이해하고 설명할 수 있는 풀스택 프로젝트 하나를 완성하는 것"입니다.
